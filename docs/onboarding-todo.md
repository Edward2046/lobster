# 新 Leader 入职指引

> 入职日期：**2026 年 6 月 17 日（周二）**
> 这份文档是我给你的落地建议，具体到每天的重点事项，供你参考和调整。不是硬性要求，而是希望帮你在前 30 天少走弯路、快速建立信任感。有任何问题随时找我。

---

## 整体节奏

> **前两周多听多问，第三周开始有序推动，一个月内建立基本信任和运转机制。**

```
Week 1  6/17–6/20   熟悉业务 + 认识团队 + 与我对齐方向
Week 2  6/23–6/27   全员 1on1 + 二次对齐目标 + 制定团队目标
Week 3  6/30–7/04   跑通周会/站会机制 + 监控治理 + 认识合作团队
Week 4  7/07–7/11   研发规范落地 + 复盘入职第一个月
```

---

## Week 1 · 6/17–6/20 · 听、看、建立第一印象

### 6/17（周二）· 入职第 1 天

**上午**
- [ ] 完成入职手续、配置开发环境
- [ ] 拿到团队花名册，了解每位同学的角色与职责
- [ ] 开始阅读产品文档 / 核心 PRD，建立业务框架

**下午**
- [ ] 约我（直属上级）当天或次日的 1on1，时间不超过 1 小时
- [ ] 走一遍产品主流程，亲手体验，记录疑问

---

### 6/18（周三）· 对齐方向

**上午**
- [ ] 与我完成首次 1on1，重点对齐：
  - 我来做什么 —— 角色定位与核心职责
  - 上级视角下团队当前最大的挑战
  - 30 / 60 / 90 天的阶段性期望
  - 我的工作风格与沟通偏好
- [ ] 记录关键信息，整理疑问

**下午**
- [ ] 继续深入业务文档（技术方案 / 架构图）
- [ ] 拉一个和团队同学的 1on1 排期表（目标：6/23–6/27 覆盖全员）

---

### 6/19（周四）· 深入业务

- [ ] 重点阅读技术架构文档，理解系统全貌
- [ ] 找 2–3 位核心同学非正式聊聊（不用正式 1on1，先破冰）
- [ ] 整理业务疑问清单，找对应同学答疑
- [ ] 参加团队日常会议（如有），观察团队协作方式

---

### 6/20（周五）· 整理 Week 1 收获

- [ ] 整理本周对业务的理解，输出一份简单的业务梳理笔记（自用）
- [ ] 确认下周全员 1on1 排期（每人 30–45 分钟）
- [ ] 和我同步本周观察，确认方向是否有偏差

---

## Week 2 · 6/23–6/27 · 全员 1on1，摸清现状

> 本周重心：**每天 2–3 个 1on1，带着问题聊，带着记录走。**

**1on1 建议问题：**
- 你目前在做什么，遇到的最大卡点是什么？
- 团队现在做得好的地方是什么？最需要改进的是什么？
- 有什么希望我优先关注的事？

### 6/23–6/26 · 全员 1on1

- [ ] 每天安排 2–3 个 1on1，覆盖全员
- [ ] 每次结束后记录关键信息：卡点、期望、行动项
- [ ] 观察团队的工作节奏、协作习惯、存在的隐性问题

### 6/27（周五）· 汇总 + 二次对齐目标

**上午**
- [ ] 整理全员 1on1 收集到的团队现状：卡点、期望、共性问题

**下午**
- [ ] 与我（上级）二次对齐：
  - 我们的判断是否一致？有没有你发现但我不知道的问题？
  - 目标是否现实可执行？优先级如何排？
- [ ] 对齐后起草团队目标初稿（季度 / 月度）
- [ ] 计划下周找时间与团队同步目标

---

## Week 3 · 6/30–7/04 · 建立团队运转机制 + 监控治理

### 6/30（周一）· 同步团队目标 + 启动站会

- [ ] 全员会议同步团队目标，收集反馈，确认共识
- [ ] 宣布站会机制正式启动：
  - 时间：每天固定时段（建议 9:30 或上午开工前）
  - 格式：三问（昨天做了什么 / 今天计划 / 有什么阻塞）
  - 时长：控制在 10 分钟以内，超时问题线下跟进

### 7/01（周二）· 认识合作团队

- [ ] 约产品、设计、QA、数据、运维各团队负责人短聊（每人 20–30 分钟）
- [ ] 了解跨团队协作流程：需求对接、联调节奏、上线审批
- [ ] 确认紧急联系人与升级路径

### 7/02（周三）· 监控治理

> 了解现状是第一步，不求立刻完善，先摸清家底、定优先级。

- [ ] 摸底现有监控覆盖情况：核心服务、接口、中间件是否有告警
- [ ] 检查告警有效性：是否存在大量误报 / 漏报 / 无人响应的告警
- [ ] 了解当前 on-call 机制：是否有值班轮转、告警响应 SLA 是否明确
- [ ] 梳理监控盲区：哪些关键链路没有可观测性（日志 / 指标 / 链路追踪）
- [ ] 输出监控治理 TODO 清单，按优先级排序，后续 Week 4 起逐步推进

### 7/03（周四）· 跑通第一次周会

- [ ] 输出标准周会模板（结构：Done / Todo / 风险阻塞 / Action Items）
- [ ] 召开本团队第一次正式周会，验证模板是否好用
- [ ] 收集反馈，调整模板细节

### 7/04（周五）· 整理 Week 3 进展

- [ ] 将团队目标、站会规则、周会模板写入团队 wiki
- [ ] 将监控治理 TODO 清单写入 wiki，同步给团队
- [ ] 和我同步 Week 3 进展与感受

---

## Week 4 · 7/07–7/11 · 研发规范落地 + 第一个月复盘

### 7/07–7/09（周一~周三）· 制定研发规范

- [ ] 和团队一起制定（不是自上而下发文件），重点几项：
  - Git 工作流：分支命名规范、commit message 规范、PR 模板
  - Code Review：审批人数、SLA 时间（建议 1 个工作日内）、关注重点
  - 上线流程：灰度策略、回滚机制、上线通知规则
  - 文档规范：接口文档、架构文档更新时机
- [ ] 规范初稿完成后发给我 review

### 7/10（周四）· 研发规范宣讲

- [ ] 组织全员宣讲，收集反馈，规范正式定稿
- [ ] 写入团队 wiki

### 7/11（周五）· 入职第一个月复盘

- [ ] 和我做一次 30 天复盘 1on1：
  - 目标对齐情况如何？
  - 团队现状和预期是否一致？
  - 下一个 30 天的重点是什么？
- [ ] 自我评估：哪些做得好，哪些需要调整
